# Support Care Management App — Backend

FastAPI backend for the Support Care Agency web app. Built API-first so the same
backend can serve both the web app now and a native mobile app later, without
rebuilding anything on the server side.

## Stack
- **FastAPI** — API framework
- **PostgreSQL (via Supabase)** — database
- **SQLAlchemy** — ORM
- **Alembic** — migrations
- **JWT (python-jose)** — auth tokens for both admin and worker sessions
- **bcrypt (passlib)** — password hashing
- **Resend** — transactional email (worker credential delivery)

## Project structure

```
app/
├── main.py              # FastAPI app creation, CORS, router registration
├── config.py            # Environment-based settings
├── database.py          # DB engine, session, Base
├── models/              # SQLAlchemy tables (one file per entity)
├── schemas/             # Pydantic request/response shapes
├── routers/             # API endpoints, grouped by resource
├── services/            # Business logic (auth, worker creation, visit rules)
├── core/                # Security (JWT/bcrypt) and auth dependencies
└── utils/               # Pure helper functions (ID generation, geofencing)
alembic/                 # Database migration scripts
```

## Setup

1. Create a virtual environment and install dependencies:
   ```bash
   python -m venv venv
   source venv/bin/activate
   pip install -r requirements.txt
   ```

2. Copy `.env.example` to `.env` and fill in your real Supabase connection
   string and a generated JWT secret.

3. Create the initial migration and apply it:
   ```bash
   alembic revision --autogenerate -m "initial schema"
   alembic upgrade head
   ```

4. Create your first admin account manually (no signup endpoint exists for
   admins on purpose — this is a deliberately closed system). You can do this
   with a short one-off Python script using `hash_password()` from
   `app/core/security.py`, or we can add a small CLI command for this next.

5. Run the server:
   ```bash
   uvicorn app.main:app --reload
   ```

6. Visit `http://localhost:8000/docs` for the interactive API documentation
   (auto-generated by FastAPI from our routers and schemas).

## What's implemented so far

- Admin login (email + password)
- Worker dual login (Employee ID + password, OR email + password)
- Admin creates worker → system auto-generates Employee ID + temp password →
  emails credentials automatically
- Forced password change + Terms & Conditions acceptance on worker's first login
- Instant worker deactivation (enforced on every request, not just at login)
- Client CRUD
- Shift creation, editing, cancelling, reassigning
- Visit lifecycle: Start Appointment → notes during visit → End Appointment
  (with mandatory summary note enforced)
- GPS coordinates captured at start/end (geofence distance-check utility is
  built but not yet wired in — needs client address geocoding first)
- Audit logging for every meaningful action
- Dashboard analytics endpoint (totals: clients, active workers, visits, hours)
- Visit/payroll report endpoint (filterable by date range and worker)

## Deliberately not yet built (next steps)
